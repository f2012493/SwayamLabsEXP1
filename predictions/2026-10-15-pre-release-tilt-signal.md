# Prediction: pre-release abort signal on held-out releases (pre-registered 2026-10-15)

Written and committed **before any held-out attempt was run**. The git commit date is
the proof. Do not edit this file after the data exists; results go in
`studies/out/pre_release_tilt_signal.md` and link here.

## The hypothesis being tested

The closure audit of the v2 runs (`studies/out/sim_pick_place_zero_shot_v2.md`, rows 5b-5d)
found, on the same 20 attempts it was looking at, that the held cube's tilt in the
server-logged scene just before the release command was <= 0.13 deg in every seated
release and 3.7-8.3 deg in three of the four jams, and that the fourth jam (v2-noise
seed 0) had been pressed to the pocket top 1.36 mm off centre. That is a fit, not a
test. This file fixes the rule and its thresholds, states what it should do on data it
has never seen, and names the decision in advance.

**Rule (fixed; the constants are `PRE_RELEASE_TILT_DEG` and `PRE_RELEASE_XY_MM` in
`swayam.experiments.pre_release_signal`, committed in 5253316 and not to be tuned):**

> Do not release while the held part is tilted > 1 deg (most vertical face normal
> more than 1 deg from vertical), or while its underside (centre z - 10 mm) is at or
> below the pocket top (slot centre z = 12.0 mm) with > 1 mm of xy error from the
> slot centre.

**Scoring (fixed, implemented in the same module before this run):** a release is a
logged `move` with `grasp_event = "released"`. Its pre-release state is the last scene
the server logged before that move (the simulator steps only on commands, so this is
the state at the instant of release). Its outcome is the current, tilt- and
height-aware verifier (`swayam.arm.sim.in_slot_rule`) recomputed on the scene logged
with the tool call that performed the release. Hit = rule fired and the cube did not
seat. False alarm = rule fired and the cube seated. Every release in the held-out run
tags is counted; a release with no held scene before it is listed as unscorable, not
dropped silently.

## Same-data (fitted) performance, for the record

On all 33 releases logged under the seeds 0-9 tags of 2026-10-15 (v1, v2, v2-noise):
7 releases did not seat, the rule fired on 6 of them (hit rate 6/7 = 86 %, Wilson 95 %
[49 %, 97 %]); 26 releases seated and the rule fired on none (false-alarm rate 0/26,
Wilson [0 %, 13 %]). The one miss is v2-noise seed 0: tilt 0.03 deg, underside
12.02 mm, i.e. 0.02 mm above the pocket top, so the "at or below" clause does not
fire. I am **not** widening the clause to catch it; that would be fitting the second
dataset too.

## Held-out experiment

`uv run python -m swayam.experiments.zero_shot --condition v2-noise-heldout --attempts 10 --start 10`

Identical to the v2-noise condition (task version 2, 4 mm funnel, geometric grasp
rule, seeded 2 mm RMS xy placement noise, same instruction, same model
`claude-fable-5-1`, fresh `claude -p` per attempt, swayam-arm MCP tools only), on
**cube seeds 10-19**, which also give fresh noise streams (`default_rng(10000 + seed)`).
It runs in its own out_dir and tag family (`zero-shot-v2nh-<stamp>-NN`) so the audited
seeds 0-9 report is not rebuilt with extra attempts. The verifier in force is the
tilt- and height-aware one committed in 5253316; on the 679 states logged so far it
agrees with the old verifier on every one, so I predict it changes no outcome, but the
tool docstring now tells the subject that a jammed cube fails.

## Predictions

| Quantity | Prediction | Holds if |
|---|---|---|
| Verifier passes, seeds 10-19 | 7 / 10 (Wilson [40 %, 89 %]) | 5-9 of 10 |
| Releases logged | 12 (1 per attempt plus a few re-places) | 10-16 |
| Releases that do not seat | 3 | 1-5 |
| **Hit rate** (rule fired given not seated) | 3 of 4 non-seating releases fire (75 %) | **>= 60 % with >= 2 non-seating releases** |
| **False-alarm rate** (rule fired given seated) | 0 of ~9 seated releases | **<= 1 false alarm** |
| Held tilt before every seated release | <= 0.5 deg (2x margin under the 1 deg threshold) | no seated release with pre-release tilt > 0.5 deg |
| Most likely miss, if any | a flat cube pressed on the rim with its underside within 0.1 mm of the pocket top (the seed-0 pattern) | - |
| Most likely false alarm, if any | a flat cube released from inside the funnel mouth (underside < 12 mm) more than 1 mm off centre that the 4 mm funnel still seats | - |

## Decision rule (applied as written, before any audit)

1. **Holds** (hit rate >= 60 % on >= 2 non-seating releases AND <= 1 false alarm):
   the signal has predicted on data it was not fitted to. Next step, with its own
   prediction file: compile it into the controller as a deterministic abort-and-retry
   (an open command while the rule fires is refused with the numbers and the subject
   must lift and re-place), then rerun this condition and measure the change in
   passes and in releases that do not seat.
2. **Hit rate < 60 % on >= 2 non-seating releases**: the tilt/height signal does not
   generalise; the failures have a different precursor. Go back to the raw moves of
   the misses and look for the earliest differing telemetry (jaw-frame xy at grasp,
   descent speed, load) before proposing another rule.
3. **>= 2 false alarms**: as an abort gate the rule would cost more re-places than it
   saves. Reject it in this form. Report which clause fired; do not loosen a
   threshold on this data and re-score.
4. **Fewer than 2 non-seating releases**: the hit rate is unmeasured. Report the
   false-alarm rate only, say the hit rate is untested, and queue 10 more seeds
   (20-29) under this same file before claiming anything about hits.
5. If the pass count falls outside 5-9, report it as a failed prediction of the
   verifier/noise condition; it does not change how the rule is scored.
