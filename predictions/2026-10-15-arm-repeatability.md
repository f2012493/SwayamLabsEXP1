# Prediction: SO-101 repeatability (pre-registered 2026-10-15)

Written and committed **before the arm arrived**. The git commit date is the proof.
Do not edit this file after the measurement; record results in a new file that
links here. The `closure-auditor` checks this.

## Claim

Using the error-budget model (`src/swayam/studies/error_budget.py`, official SO-101
kinematics, ±0.5° backlash per joint, 4096-count encoders), in the work zone in front
of the arm:

| Scenario | Predicted 95th-percentile gripper error (median over poses) |
|---|---|
| Return to a pose, approaching from **any** direction | **3.7 mm** |
| Return to a pose, approaching from the **same** direction (overshoot 3°, then approach) | **0.5 mm** |
| Ratio any / same | **about 7×** |

The model also predicts the shoulder pan, shoulder lift and elbow joints each move the
gripper about 4 mm per degree of joint error, and wrist roll almost nothing (0.14 mm
per degree).

Not predicted here: placement on camera-located targets. That depends on calibration
and camera error, which Phase 0 measures first.

## Protocol (ROADMAP Phase 0, step 2)

1. Arm clamped to the table, warmed up by 10 minutes of motion, same power supply
   as production.
2. Use these five poses, fixed by seed before the arm existed
   (`uv run python -m swayam.studies.error_budget --protocol`):

   | Pose | shoulder_pan | shoulder_lift | elbow_flex | wrist_flex | wrist_roll | Predicted any / same (mm) |
   |---|---|---|---|---|---|---|
   | 1 | -58.4 | -31.3 | 12.4 | 82.4 | 135.6 | 3.11 / 0.42 |
   | 2 | -43.6 | -43.6 | 77.1 | 15.8 | -95.9 | 3.84 / 0.52 |
   | 3 | -16.6 | -27.9 | 75.6 | -12.5 | 77.7 | 3.88 / 0.52 |
   | 4 | 31.5 | -63.3 | 51.0 | 50.9 | 137.4 | 3.54 / 0.46 |
   | 5 | -39.0 | -47.8 | 79.2 | 17.7 | -103.0 | 3.81 / 0.50 |

   First check in the simulator that each pose looks the same on the real arm (joint
   sign conventions). If a convention differs, map the angles and note it; do not
   choose new poses.
3. For each pose, two blocks of 50 returns:
   - **any direction**: before each return, move to a random staging pose (seeded),
     then `move_joints(pose, same_direction=False)`;
   - **same direction**: the same, with `same_direction=True`.
4. Instrument: a **bought** dial indicator (0.01 mm) on a magnetic base, touching a
   flat face near the gripper. Measure x, y and z in separate runs of the blocks.
   Combine per-axis 95th percentiles as the root-sum-square to get the 3D figure.
   A camera/ChArUco measurement may be recorded alongside, but the dial indicator
   decides.
5. Every return goes into `runs/` through the arm server. No returns are dropped.

## Decision rule

- The prediction **holds** for a scenario if the measured value (median over the five
  poses of each pose's 95th percentile) is between **half and double** the prediction:
  any direction 1.9–7.4 mm; same direction 0.25–1.0 mm.
- The **ratio claim holds** if any / same is at least **3×**.
- If either fails, the model is wrong in a way worth knowing. Next step: measure the
  backlash of each joint alone, and look for unmodelled sources (gravity sag, base
  flex, link-length error). Update the model, then make a new prediction in a new file.
